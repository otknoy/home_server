# メトリクス収集の方針

家庭内サーバーの状態把握と長期比較に必要な情報を残し、系列数・収集負荷・保存容量を抑える。

- **収集間隔は用途に合わせる。** デフォルトは1分とし、温湿度を含む Service の収集だけ30秒を明示する。Grafana には1分収集を設定し、node-exporter のレート計算には `$__rate_interval` を使って計算窓を確保する。
- **未使用で系列数の多いメトリクスを絞る。** 既存のグラフ・アラートで使わない API Server 関連の8種類のヒストグラムは `_bucket` を除外し、件数・平均値に使える `_count`・`_sum` を残す。対象の分位点は計算できないため、遅延分布の監視が必要になったら見直す。
- **Kubernetes ラベルは必要なものだけコピーする。** ホスト名やアプリケーション識別用に限定し、ロールアウトのハッシュやバージョンによる不要な系列の増加を抑える。`namespace`・`pod`・`service`・`instance` は維持する。
- **保存期間は2年を維持する。** 年単位の比較を優先し、容量削減は不要系列と収集頻度の見直しで行う。
